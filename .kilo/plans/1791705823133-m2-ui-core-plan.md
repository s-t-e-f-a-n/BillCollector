# BillCollector — M2: UI core (execution plan)

Master plan: `.kilo/plans/1790364274061-billcollector-nicegui-daemon-plan.md` (v3,
M2 section). Dashboard spec: `.kilo/plans/1790468502492-gui-concept-dashboard-spec.md`
(the dashboard line in v3 is superseded by it). M1 is complete and committed to `dev`
(C7.6 exit validation done 2026-10-11; full unit suite 155/155 green).

**Goal:** the full task lifecycle is operable from the web UI against the mock portal —
login, dashboard, task management, run now/stop with live log, task detail with history
and step screenshots, recipe editing with validation + git commit, downloads, settings.
Session *view* (Copilot + noVNC) and the recipe repair flow stay in M3; in M2 the UI
surfaces pauses read-only (badge, prompt, deadline, pause screenshot) — resolution is
still via the control socket (as in M1).

## Locked decisions

1. **Auth (v3 decision 5, confirmed):** session-cookie login, bcrypt hash in
   `Settings.ui_password_hash`; `BC_UI_PASSWORD` from `.env` seeds the hash on first
   start when set. **First start with neither:** the login page shows a one-time
   *set-password* form (user-confirmed 2026-10-11); afterwards it is the normal login
   form. Password changeable in the Settings page. Single operator, no multi-tenancy.
2. **Middleware:** app-level Starlette `SessionMiddleware` (secret persisted in the
   `Settings` table as `session_secret`, generated on first start so sessions survive
   daemon restarts) redirects unauthenticated requests to `/login`; public paths:
   `/login`, `/_alive`, and NiceGUI static `/_*`. Protected page functions additionally
   check the session defensively (page builders run server-side per navigation).
3. **Test stack (v3 validation line, user-confirmed 2026-10-11):** `pytest` as a
   **dev-only** dependency (`apps/requirements-dev.txt`, never in the runtime
   `requirements.txt`); `nicegui.testing` `User` (no browser) for page-logic tests and
   `Screen` (real Chromium) where layout matters. Existing `unittest` files are
   collected by pytest unchanged. Suite command becomes
   `apps/.venv/bin/python -m pytest tests/ -q` from the repo root. M2 exit E2E on the
   mock portal stays a **recorded manual pass** (M1 C7.6 pattern) — the committed suite
   stays fast and display-independent.
4. **`apps/bc_ui.py` is deleted in M2** (user-confirmed): Run now + log pane +
   orchestrator orphan cleanup fully replace it; the legacy batch path stays available
   via `BillCollector.sh`/cron until M4. Its `pages` broadcast pattern is absorbed into
   the orchestrator's log-subscriber API.
5. **Recipe validation core:** new `billcollector/recipes.py` (YAML load + jsonschema
   against `config.RECIPE_SCHEMA`, returns `(ok, error, data)` — no legacy import, no
   `exit()` path) used by the recipe editor and (M3) the repair flow. The legacy
   `BillCollectorCheckRecipe.py` is left unchanged for the batch/CLI path.
6. **Live log:** the orchestrator's monitor pushes each stdout line to registered
   subscriber callbacks (`add_log_subscriber`/`remove_log_subscriber`); pages register
   on connect, unregister on disconnect. A page opening a finished run first loads the
   existing `Run.log_path` file, then follows.
7. **Stop:** new `orchestrator.stop_run(task_id)` — SIGTERM the runner's process group,
   escalate SIGKILL after 10 s (dashboard spec; `bc_ui.py` semantics). The runner's own
   SIGTERM handler finalizes the run `interrupted` (C7.5).
8. **Profile reset:** rejected while the task is `running`/`waiting`; deletes the
   profile dir; records `Task.profile_reset_at` (new column, additive migration via
   `PRAGMA table_info`). Next run cold-starts.
9. **Task creation fields:** service, user, cron (default `0 0 1 * *`), enabled.
   `recipe_file` is derived from the service (read-only in the UI: the recipe is
   shared by all tasks of the service — made explicit). A missing recipe file warns but
   does not block creation (the run would fail pre-recipe-check, task released by the
   orchestrator's no-row path). Every create/enable/cron change calls
   `scheduler.sync_task`. No task deletion in M2 (disabling is the off switch).
10. **Screenshots/static:** `config.RUN_DIR` (`<data>/runs/<run_id>/…`) is registered as
    a NiceGUI static directory named **`runfiles`** (`/runfiles/<run_id>/step_N.png`,
    `pause_N.png`) — deliberately not `/runs`, which is reserved for the ntfy deep-link
    route. The deep link `/runs/<run_id>` (M2: the session view is M3) redirects to the
    task detail page of the run's task.
11. **Pause surfacing in M2 (read-only):** dashboard `waiting` badge + highlighted row;
    task detail shows pause prompt, reason, deadline countdown, and the last pause
    screenshot (from `Run.pause_context` / `pause_<n>.png`). Copilot/noVNC resolution
    is M3.
12. **Settings page fields:** UI password (change), `ntfy_topic`,
    `pause_deadline_seconds`, `max_concurrency` (takes effect on next daemon start —
    the semaphore is built at construction), `git_commit_enabled`, `download_dir`,
    `display_start`, `ui_base_url`, `vnc_password`. All in the `Settings` table.
13. **Git auto-commit (v3 decision 8):** `gitcommit.py` — `git add` + commit of the
    recipe file only, message `recipe(<service>): <summary>`, only when
    `git_commit_enabled`; "nothing to commit" is a success, not an error.
14. **Layout:** shared NiceGUI layout (header + left menu: Dashboard, Downloads,
    Settings; per-task and per-recipe pages under it), login page standalone. English UI
    (v3 decision 17). `serve` binding unchanged (127.0.0.1:8000 default, env override).
15. **ini import:** already implemented (M1: `import_ini` on first `serve` start,
    marker in `Settings`). M2 only exercises it in the E2E pass — no work item.

committed. Commit style follows the repo convention (`feat:`/`test:`/`doc:` +
`(M2 chunk D<n>)`).

### D3 — Run actions + task management

*Progress (2026-10-11, D3.1):* `orchestrator.stop_run(task_id,
timeout=STOP_TIMEOUT)` — SIGTERMs the task's live runner group, then
SIGKILLs after `timeout` (STOP_TIMEOUT = 10 s, the dashboard spec value,
pinned in the tests; injectable so the suite stays fast). The
orchestrator only signals; the runner's own C7.5 SIGTERM handler or the
monitor finalizes the run (a graceful runner result is never
overwritten), and the monitor releases the task and the global slot as
usual. Returns False when there is no live runner. Unit
(`tests/test_bc_orchestrator.py` `StopRunTests`, reusing the C7.5
signal stubs): a sleeping stub (no handler) dies on the group SIGTERM
→ run `interrupted`, task `idle`; a graceful stub keeps its own
`interrupted` result; a stubborn stub's whole group (incl. a `sleep`
grandchild) is SIGKILLed after the grace; no-op without a live runner.
Full suite 189/189 green.

*Progress (2026-10-11, D3.2):* dashboard run actions in `ui/dashboard.py`
(all through the orchestrator callbacks, the same the scheduler uses): row

## Risks

- **nicegui.testing on this host:** `Screen` tests drive a real Chromium via the repo
  browser build (`PLAYWRIGHT_BROWSERS_PATH` in `tests/conftest.py`); `User` tests need
  no browser. If `Screen` proves flaky, page-logic tests stay on `User` and the manual
  E2E pass (D6.4) is the browser proof — the committed suite must not depend on a
  display.
- **APScheduler next-run display:** `next_run` is read from the live jobstore
  (`trigger.next_fire_time`), not the Task table — after a daemon restart the jobs are
  resynced from the Task table, so the display stays correct; a disabled task has no
  job → `—`.
- **Static dir vs deep link:** `/runfiles` vs `/runs/<id>` are deliberately distinct
  (D2.3/D4.2) — keep the naming when adding M3 routes.
- **SQLite writers:** UI writes (Task/Settings) are short single-row writes; the WAL +
  busy_timeout regime from M1 is unchanged.
- **git commit in the UI:** the repo is a bind mount on the NAS, single operator →
  conflicts unlikely; only the recipe file is staged (never `git add -A`); the toggle is
  off by default.
- **Session secret persistence:** the `Settings` row must be written **before** the
  first request is served (startup), otherwise sessions die on every restart.
- **`bc_ui.py` removal:** no code path imports it (it is a standalone script); verify
  nothing in docs/CI references it before deleting.
