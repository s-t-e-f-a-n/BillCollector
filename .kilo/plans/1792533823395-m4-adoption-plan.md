# M4 — Adoption for other users (execution plan)

**Goal (from the daemon plan, M4 section):** a new user sets up the stack
from the docs and collects a document from the mock portal — without shell
access to the daemon. Work items: (1) onboarding wizard (first start: set
password, vault config, ini import, first task), (2) Docker Compose package
(BillCollector, optional ntfy), (3) README/docs: daemon mode, UI usage,
recipe authoring, cron→daemon migration, F5 debug workflow
(`python -m billcollector run <task_id> --debug`), (4) mark
`BillCollector.sh` / cron as deprecated.

## Current state (verified 2026-10-20, read-only)

- **First start today:** `serve` (`apps/billcollector/cli.py`) runs
  `database.import_ini(config.INI_FILES)` (one-time: only while the Task
  table is empty; sets Settings `ini_imported`) and
  `ui_auth.ensure_password` (seeds the hash from `BC_UI_PASSWORD`). The
  `/login` page (`ui/login.py`) shows a one-time set-password form while no
  hash is stored; a successful first-start POST redirects to `/`.
- **Vault config is env-only:** `apps/.env` `BW_API_URL` (read via
  `config.env` in `runner._vault_preflight` (~L211) and `run_task` (~L816));
  `BW_API_HOST` is read directly from the environment in
  `apps/vault_transport.py:67`. In the container `apps/.env` is mounted
  read-only, so a new user cannot fix a wrong URL from the UI — there is no
  Settings row for the vault today. `apps/.env.example` documents both keys.
- **Settings page** (`ui/settings.py`) edits the Settings-table fields
  (ntfy topic, pause deadline, concurrency, display, download dir,
  `ui_base_url`, VNC password, git auto-commit) — no vault fields.
- **No compose file.** The image is built from the root `Dockerfile` by
  `install_docker-image.sh` (NAS) or a plain `docker build`; container
  semantics recorded in the wave1-nas-deploy plan (Stage 1 logs):
  `BC_UI_HOST=0.0.0.0` mandatory for off-host access, websockify range
  `6080-6095` must be published for the noVNC tab, `apps/.env` mounted
  read-only at `/apps/.env`, `CMD` is `/bin/bash` so the daemon needs an
  explicit command (`python3 -m billcollector serve`).
- **ntfy:** `notify.py` pushes to `$NTFY_HOST` (default `https://ntfy.sh`)
  + topic from Settings `ntfy_topic`. No self-hosted ntfy is shipped.
- **Docs:** README leads with the cron-driven batch flow (clone → `.env` →
  `install_docker-image.sh` → `BillCollector.sh` in cron) and treats the
  daemon as a side feature ("keeps working unchanged alongside").
  `BillCollector.sh` (flock + `docker run … BillCollector.py`) is the
  legacy cron wrapper; nothing is marked deprecated yet.
- **Debug:** `python3 -m billcollector run <task_id> --debug` exists
  (`cli.py`); the runner always runs headful on an allocated Xvfb display
  (noVNC live view on the websockify port), `--debug` adds a
  press-Enter-before-each-step stdin pause (`runner._debug_wait`). The
  README's "Local Development & Debugging" still documents F5 on
  `BillCollector.py` (legacy) only.
- **Tests:** pytest suite in `tests/` (UI pages driven with
  `nicegui.testing.Screen`; `conftest.py` redirects `BC_*` paths to a temp
  dir); full regression `tests/run_regression.py` against the mock portal;
  `tests/check_docker_context.py` uses a fixed synthetic canary list (a new
  root file does not change its expectations); ruff lint on maintained
  source.
- **Mirror:** `sync_github.sh` strips `.kilo .vscode .private openwiki
  AGENTS.md …`; everything else (README, Dockerfile, a new compose file,
  `BillCollector.sh`) is public.

## Decisions (locked for this plan)

1. **Onboarding = `/login` (set password) → `/onboarding` (wizard),**
   gated by the new Settings key `onboarding_done`.
   - **Active** while `onboarding_done` is unset. Authenticated requests to
     any path except `/onboarding` redirect to `/onboarding`
     (extension of `AuthRedirectMiddleware`, which already receives `db`).
   - The `/login` first-start POST redirects to `/onboarding` when the
     wizard is active, else `/` (today it always goes to `/`).
   - **Auto-complete for upgraded installs** (so the NAS cutover is not
     interrupted): at `serve` startup, after `ensure_password`, if
     `onboarding_done` is unset **and** a password hash exists **and** at
     least one task is enabled → set `onboarding_done=1`. A fresh install
     (no hash, or no enabled task) still gets the wizard.
   - The set-password step stays in `/login` (existing form + validation);
     the wizard covers the remaining steps.
2. **Wizard steps (single `/onboarding` page, NiceGUI stepper, auth
   required):**
   1. **Vault** — `BW_API_URL` + optional `BW_API_HOST` inputs, a
      **Check** button (DNS vetting via `pinned_api_urls` +
      `bitwarden_api_check_status`; shows unlocked/locked/network error),
      and **Save**, which writes new Settings keys `vault_api_url` /
      `vault_api_host` (empty allowed = env fallback). "Skip for now" is
      allowed but flagged: runs fail at vault preflight until configured.
   2. **Tasks** — the imported task list (id, service, user, enabled,
      cron, whether the recipe file exists), buttons: **Import from INI**
      (re-run `import_ini` with a new `force=True` flag: skips the
      empty-table guard, the existing (service, user) duplicate guard
      still applies, so it re-adds only entries missing from the table —
      including ones the user deleted; the result count is shown),
      **New task** (service, user, cron, enabled; recipe path + profile
      dir derived as in `import_ini`), and per-task enable toggles.
   3. **Finish** — summary + **Finish onboarding** (writes
      `onboarding_done=1`, navigates to `/`); pointers to Settings for
      `ui_base_url` (ntfy deep link) and `ntfy_topic`.
3. **Vault resolution order:** Settings `vault_api_url` → env `BW_API_URL`
   (same for host). Resolution lives in one helper
   (`config.vault_settings(db)` returning `(api_url, api_host)`); the
   runner exports the effective values into `os.environ` before the vault
   calls, so `vault_transport.vault_http_request` (which reads
   `BW_API_HOST` from the environment) and the legacy batch entry point
   (env-only) keep working unchanged. The wizard's Check button applies
   the same export for the duration of the check.
4. **Compose** — `docker-compose.yml` at the repo root (public): service
   `billcollector` built from the root `Dockerfile`, command
   `python3 -m billcollector serve`, `BC_UI_HOST=0.0.0.0`, UI port
   `${BC_UI_PORT:-8766}:8000` + websockify `6080-6095`, volumes
   `./apps/.env:/apps/.env:ro`, `./apps/Downloads`, `./apps/db`,
   `./apps/data`, `./apps/browser`, `extra_hosts:
   host.docker.internal:host-gateway` (reaches a host-local mock portal /
   vault from the container), optional `ntfy` service behind compose
    profile `ntfy` (image `ntfy/ntfy`, port `2086:80`, named volumes,
   `NTFY_BASE_URL` passthrough); with it enabled, the billcollector
   service gets `NTFY_HOST=http://ntfy`. Variables come from an optional
   root `.env` (compose substitution; the deploy script's root `.env` keys
   are disjoint). Vaultwarden stays a prerequisite (own compose per its
   repo).
5. **Docs** — README restructured, daemon mode as the primary Quick Start:
   prerequisites → clone → `cp .env.example .env` → `docker compose
   up -d --build` → set password → wizard → first task. Existing
   Vaultwarden / DuckDNS / NPM material stays. New sections: daemon mode
   (env vars, Settings, container semantics), UI usage (per page), recipe
   authoring (kept + `wait_user`/`graceful`/dedup notes + in-UI editor),
   **cron → daemon migration** (import, per-task cron, verify one run,
   then stop the cron entry; rollback = re-enable the cron entry; the
   shared `apps/.bc.lock` flock keeps an accidental double start safe), and
   the **F5 debug workflow** (`python -m billcollector run <task_id>
   --debug`: headful on an Xvfb display with noVNC, press-Enter step
   pause, VS Code launch-config snippet in the README — no `.vscode/`
   committed, it is mirror-stripped). The legacy batch section gets a
   **deprecated** banner. CHANGELOG `[Unreleased]` entries for the wizard,
   compose, docs, and deprecation.
6. **Deprecation** — `BillCollector.sh` keeps working (it is the rollback
   path): header comment + a runtime stderr notice that the batch/cron
   mode is deprecated and the daemon replaces it. No file removal.

## M4 exit pass (user-gated, needs a Docker host)

Guide: `.kilo/plans/1792533823395-m4-exit-pass-guide.md` (written after
C1–C5 land). The pass plays a new user from the README alone:

1. Fresh clone (or a clean checkout) on a Docker host with a running
   Vaultwarden + `bw serve` (or, for the mock-portal half, the repo's
   `tests/mock_portal` on the host).
2. `cp .env.example .env`, `docker compose up -d --build`, open the
   published UI port from the LAN.
3. Set the password → walk the wizard (vault check green against the local
   vault, or skip-and-flag; create the first task pointing at the mock
   portal via `host.docker.internal:8787`).
4. Enable the task → **Run now** from the UI → run reaches `success` →
   the document is visible on the Downloads page and in the consumer
   folder — every step driven from the browser, no daemon shell.
5. Optional half: `docker compose --profile ntfy up -d` + a pause drill
   (`testwaituser`) with the phone push.

## Risks / failure modes

- **Upgraded install interrupted by the wizard** — mitigated by the
  auto-complete rule (hash + enabled task). If the rule misfires, the
  wizard is harmless: finish it in one pass or set
  `onboarding_done=1` in Settings-free SQL (documented in the guide).
- **Wizard check button blocks the UI** — the vault check is synchronous
  with a 10 s timeout × 3 attempts in the worst case; it runs in the
  NiceGUI event loop. Acceptable for a one-time step (the preflight in
  runs has the same profile); noted, not fixed.
- **Compose on a host without `apps/.env`** — docker creates a *directory*
  for a missing bind-mount file, breaking the mount. The README quick
  start makes `cp .env.example .env` a numbered step before `up`.
- **`NTFY_HOST` confusion** — empty default = public `ntfy.sh`; the
  compose comment documents the exact two-line change to use the bundled
  ntfy.
- **README rewrite scope creep** — the legacy material (Vaultwarden,
  DuckDNS, NPM, regression env, build context, layer cache) is preserved,
  only reordered and annotated; no section is dropped.
- **Docker unavailable locally** — C3's live build is deferred to the
  exit pass on a Docker host (NAS or any other); nothing in C1/C2/C5
  requires a Docker daemon.
