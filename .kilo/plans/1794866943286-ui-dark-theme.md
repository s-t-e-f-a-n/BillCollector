## Goal

One dark-skin pass over the Web UI — the "fintech precision" design layer:
design tokens, `theme.py`, chrome reskin, header icon / version chip /
"Daemon active" pill, dashboard KPI strip, dark-readability audit, CodeMirror
dark theme, login restyle. Dark is the app's only skin (no light mode, no
toggle). All UI text stays English.

## Locked decisions (planning session 2026-11-16, recovered)

- **Theme**: dark. bg `#090d16` (slate-950), surface `#0f172a` (slate-900), 1px
  borders `#1e293b` (slate-800), no shadows. Primary emerald `#10b981` (hover
  `#059669`), warning amber `#f59e0b`, danger rose `#f43f5e`, running sky
  `#0ea5e9`. Text `#f1f5f9` / `#94a3b8` / `#64748b` (primary / secondary / muted).
- **Typography**: system font stacks only — no external font CDN (self-hosted NAS,
  must work offline). Sans: `ui-sans-serif, system-ui, -apple-system, "Segoe UI",
  Roboto, sans-serif`; mono: `ui-monospace, "SF Mono", Menlo, Consolas, monospace`
  for technical data (cron, checksums, log lines, KPI values).
- **Status axes stay two**: task status (idle/running/waiting → slate/sky/amber)
  and run result (success/failure/interrupted/cancelled/needs_attention →
  emerald/rose/muted).
- **No dark-mode toggle** (locked; a toggle is a later, separate decision).
- **Header**: app icon + name + version chip (from `billcollector.__version__`)
  left; "Daemon active" pill with a pulsing emerald dot right. No add-task button
  or gear in the header (they stay in the dashboard toolbar / drawer).
- **Mouse-over text** (user decision, 2026-11-16; scope confirmed 2026-11-17):
  hover tooltips on **all** new chrome elements — the version chip (full version
  string), the "Daemon active" pill (scheduler state + version), and the three
  KPI cards (one-line explanation of what each counts).
- **Prerequisite**: the navigation pass (5-item icon drawer, `/tasks`,
  `/recipes`, icon actions) is delivered first; this plan reskins its output and
  adds the KPI strip. No page-structure or behavior changes.

## Verified environment facts (NiceGUI 3.17.1 in `apps/.venv`; re-verified on reconstruction)

- **Tailwind**: `ui.run(tailwind=True)` is the default; the runtime JIT engine
  (`tailwindcss.min.js`) is bundled locally in `nicegui/static` → arbitrary and
  dynamically built utility classes (e.g. `bg-{hue}-500/10`) work, fully offline.
- **`ui.dark_mode()`** (`nicegui/elements/dark_mode.py`): `.enable()` /
  `.disable()` / `.auto()`; overrides the `dark` parameter of `ui.run`. Dark is
  applied per page via `apply_theme()` in `build_layout` (keeps the public
  `/login` controllable); `ui.run` keeps the default `tailwind=True` and no
  `dark` parameter.
- **`ui.colors()`** (`nicegui/elements/colors.py`): per-page Quasar theme, kwargs
  `primary/secondary/accent/dark/dark_page/positive/negative/info/warning` +
  `**custom`; takes precedence over the global `app.colors()`.
- **`billcollector.__version__`** exists (`billcollector/__init__.py`, currently
  "0.1.0") — the version chip's source.
- **CodeMirror**: `ui.codemirror` has a first-class `theme` prop (default
  "basicLight"); **`oneDark` is bundled locally** (`@codemirror/theme-one-dark`
  in `nicegui/elements/codemirror/dist`, registered in `codemirror.js` as
  `this.themes.oneDark`) → `editor.set_theme("oneDark")` is offline-safe. The
  pre-split plan's "light paper block" fallback is no longer needed.
- Material Icons + Roboto are bundled locally → `ui.icon(...)` is offline-safe.
- **Fixed-color classes that break dark readability** (re-verified 2026-11-17; the
  Quasar-grey block matches the pre-split audit line-for-line — the code has not
  changed since):
  - Quasar grey text: `text-grey-6/7/8/9` in `settings.py` (92, 137, 160),
    `session.py` (465, 491, 675, 690, 740, 759, 762), `onboarding.py` (70, 83,
    178, 189, 197, 204, 331), `tasks.py` (58, 66, 94), `recipes.py` (144, 147,
    172, 174, 178, 255, 261, 306), `dashboard.py` (323), `task_detail.py`
    (332, 357).
  - Fixed light-mode surface/accent classes: `layout.py:26` header
    `bg-slate-800 text-white`; `layout.py:28` drawer `bg-slate-100` + active item
    `bg-blue-200` (line 33); `session.py:743` card `bg-slate-50`;
    `session.py:640,736` links `text-blue-700`; the dashboard `ROW_BODY`
    waiting-row highlight `bg-amber-100` (line 96); the recipe failure panel
    `bg-red-50` / `text-red-900` / `text-red-800` (`recipes.py` 242–259);
    `text-red-600` in `login.py:64`, `task_detail.py:152`, `session.py:275`,
    `recipes.py:302`; `text-green-700` in `recipes.py:314`; `text-white` in
    `session.py:95` (overlay number on a colored chip — **kept**).
  - Hand-rolled light-mode CSS in `login.py` (`_FORM_CSS`: `#ccc` borders,
    `#1976d2` button).
- **KPI data sources**: `dashboard.next_run(scheduler, task_id)` (dashboard.py:125)
  reads the APScheduler job's `next_run_time` (job id `task-<id>`, via
  `job_id_for`) and returns it *formatted* (`%Y-%m-%d %H:%M:%S` or `—`) — the
  KPI countdown therefore needs its own small helper over the same jobstore
  pattern (raw datetimes, min over enabled tasks). `db.list_downloads()` rows
  carry `created_at`; `Task.status` ∈ idle/running/waiting.
- **Test harness**: `pytest.ini` (`addopts = -p nicegui.testing.user_plugin`,
  `main_file = tests/ui_test_main.py`) → browserless `User` simulation against the
  production `build_app` wiring on a fresh temp DB; UI tests assert on `.mark()`
  ids, never label text → a presentation-only pass is test-safe as long as all
  markers are preserved.

## Tasks

### D1 — Theme layer `apps/billcollector/ui/theme.py` (new)

- Constants for the token table + `apply_theme()`, called at the top of
  `build_layout` so every protected page inherits the theme:
  - `ui.dark_mode().enable()`;
  - `ui.colors(...)` with the locked tokens — primary `#10b981`, positive
    `#10b981`, negative `#f43f5e`, warning `#f59e0b`, info `#0ea5e9`, dark
    `#0f172a`, dark_page `#090d16` (signature verified in 3.17.1, see above);
  - one `ui.add_head_html` block: body background/text, the two font stacks,
    the Quasar `.q-body` background, and a thin dark scrollbar.
- Helpers: `pill(hue, label)` → classes, `card()` → classes,
  `kpi_card(title, value, sub)` → element builder (mono value, uppercase
  tracked label, 1px border, no shadow).
- `ui.run` in `app.py` keeps the default `tailwind=True` and no `dark` parameter.

### D2 — Chrome reskin (`layout.py`)

- `apply_theme()` called at the top of `build_layout`.
- Drawer: ~220px, `bg-slate-950 border-r border-slate-800`; items stay
  icon + label rows (the icons come from the navigation pass); active item =
  emerald tinted pill (`bg-emerald-500/10 text-emerald-400
  border-emerald-500/20`), inactive `text-slate-400 hover:text-slate-200
  hover:bg-slate-900`.
- Header: flat `bg-slate-950 border-b border-slate-800`, no shadow: left = small
  app icon + "BillCollector" + version chip (mono, `bg-slate-800
  text-slate-400`,   `billcollector.__version__`) with a hover tooltip showing the full version
  string; right = "Daemon active" pill with a pulsing emerald dot, with a hover
  tooltip showing the scheduler state + version.
- Keep the `build_layout(active=...)` signature and all `.mark()` ids
  (`header`, `left-menu`, `menu-*`).

### D3 — Dashboard KPI strip (`dashboard.py`, additive)

- Above the toolbar, `ui.grid(columns=3)` with the three `kpi_card`s:
  1. **Tasks** — value `enabled/total` (e.g. `12/14`); sub = `N running ·
     M waiting` (from `Task.status`) or `all idle`.
  2. **Downloads (30 days)** — value = count of `Download` rows with
     `created_at` ≥ now − 30 d (all delivery states); sub = newest
     `created_at` as `YYYY-MM-DD` or `—`.
  3. **Next run** — value = countdown `in HH:MM:SS` (min `next_run_time` over
     enabled tasks, recomputed on the existing 2 s poll; `—` when none); sub =
     that task's `service/user`. New small helper (e.g.
     `next_run_countdown(scheduler, db)`) mirroring `next_run`'s jobstore
     pattern but returning raw datetimes — the existing helper is
     display-formatted and cannot be reused for the min/countdown.
- KPI cards carry the hover tooltips: a one-line explanation of what each
  counts (e.g. Tasks → "Enabled/total tasks; running and waiting right now").
- The table, toolbar, log pane, and step strip stay structurally untouched
  (they pick up the new skin via the theme + the D4 fixes).

## Risks & mitigations

- Quasar components (q-table, q-select, q-dialog) adapt to dark mode
  automatically — verify dropdown/dialog surfaces visually in D7; fix
  stragglers with D4-style classes.
- `ui.colors` retunes Quasar's built-in button/badge colors app-wide; the
  locked token values make this deterministic — verify the colored controls in
  D7.
- The KPI "Next run" countdown is computed per connection on the existing 2 s
  poll (NiceGUI pages are per connection) — the app's existing regime, fine
  for a NAS.
- The navigation pass must land first; if it is not done when this plan starts,
  the chrome reskin (D2) and the KPI strip's toolbar placement (D3) are blocked
  — implement in order, do not interleave.
- No `.kilo/plans` paths or plan IDs in source comments or public docs — the
  sanitized GitHub mirror must stay clean (private-agent-artifact rule in
  `AGENTS.md`).
